lint-staged runs your formatters, linters and other tools on the files that you stage in Git, before each commit. It does not run them on the full project. Thus the check before a commit is fast, and it shows only the errors in the files that you changed.

These are community docs for lint-staged 17.6. They are unofficial: the [lint-staged project](https://github.com/lint-staged/lint-staged) does not maintain this site. The pages are written from the lint-staged source code, and each example was tested with lint-staged 17.6.1. For the official text, read the [lint-staged README](https://github.com/lint-staged/lint-staged#readme). See [About these docs](/about).

```text
$ git commit

⋯ Backing up original state…
✔ Done backing up original state (b747171)!
⋯ Running tasks for staged files…
    *.js — 1 file
      ⋯ prettier --write

✔ prettier --write

✔ Done running tasks for staged files!
⋯ Staging changes from tasks…
✔ Done staging changes from tasks!
⋯ Cleaning up temporary files…
✔ Done cleaning up temporary files!
```

## Requirements

| Item | Requirement for lint-staged 17.6 |
| --- | --- |
| Node.js | 22.22.1 or later |
| Git | 2.32.0 or later |
| Repository | At least one commit, for the backup stash. See [How it works](/how-it-works). |

lint-staged makes sure that the Git version is 2.32.0 or later before each run. If Git is older, lint-staged stops with an error.

## Related tools

If you only want to check the staged files for errors, and not change them, the lint-staged team also has a shell script: [lint-staged.sh](https://github.com/lint-staged/lint-staged.sh).
